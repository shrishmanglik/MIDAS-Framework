# Pricing Table Template

> Use this template to present pricing in proposals, pitch decks, and sales materials. Pricing should always appear AFTER value has been established. Never present a price without context.

---

## Instructions

1. Choose the pricing structure that matches your deal type
2. Replace all `[BRACKETED]` placeholders with specific amounts and details
3. Always include a value justification section — price without context invites negotiation
4. Include at least one comparison point (ROI, payback period, cost-per-unit, build-vs-buy)
5. Payment terms must be explicit — amounts, dates, consequences

---

## Pricing Structures

### Structure A: Project-Based Pricing

Use for fixed-scope engagements with defined deliverables.

```markdown
## Investment

### Project Fees

| Component | Description | Investment |
|-----------|-------------|-----------|
| [Component 1] | [What this covers] | $[amount] |
| [Component 2] | [What this covers] | $[amount] |
| [Component 3] | [What this covers] | $[amount] |
| [Component 4] | [What this covers] | $[amount] |
| **Total Project Investment** | | **$[total]** |

### Payment Schedule

| Milestone | Amount | Trigger |
|-----------|--------|---------|
| Deposit | $[amount] ([X]%) | Upon SOW execution |
| Milestone 1 | $[amount] ([X]%) | Upon [specific deliverable] acceptance |
| Final payment | $[amount] ([X]%) | Upon [launch / final acceptance] |

### Value Context

**Your investment**: $[total]
**Expected return**: [Quantified client outcome — e.g., "$X/month in additional revenue"]
**Payback period**: [X months]
**After payback**: [Ongoing benefit — e.g., "$X/month net positive"]
```

## Value Justification Frameworks

Always pair pricing with one or more of these frameworks:

### Framework 1: ROI Calculation

```markdown
### Return on Investment

| Metric | Value |
|--------|-------|
| **Your investment** | $[total price] |
| **Expected monthly return** | $[quantified benefit]/month |
| **Payback period** | [X] months |
| **12-month net return** | $[12-month benefit minus cost] |
| **ROI** | [percentage]% |

*Calculation basis*: [Explain the assumptions — e.g., "Based on X additional premium conversions at $Y/month"]
```

### Framework 2: Cost Comparison (Build vs. Buy)

```markdown
### Build vs. Buy Analysis

| Factor | Build In-House | Buy from Us |
|--------|---------------|-------------|
| Development cost | $[estimate] ([X] hours at $[rate]/hr) | $[our price] |
| Time to market | [X] months | [Y] weeks |
| Ongoing maintenance | $[amount]/month (developer time) | $[amount]/month (included) |
| Risk | [High — unproven, may need iteration] | [Low — proven, 99.9% uptime SLA] |
| **Total Year 1 Cost** | **$[build total]** | **$[buy total]** |
| **Savings with us** | | **$[difference] ([Z]%)** |
```

### Framework 3: Cost Per Outcome

```markdown
### Cost Per [Outcome]

| Metric | Calculation |
|--------|------------|
| Total annual investment | $[amount] |
| Expected [outcomes] per year | [number] |
| **Cost per [outcome]** | **$[amount]** |

*Comparison*: Industry average cost per [outcome] is $[benchmark]. Our solution delivers at [X]% of industry cost.
```

### Framework 4: Competitive Pricing Context

```markdown
### Market Context

| Provider | Price | Includes |
|----------|-------|----------|
| [Competitor 1] | $[price] | [What they include — highlight gaps] |
| [Competitor 2] | $[price] | [What they include — highlight gaps] |
| **Us** | **$[our price]** | **[What we include — highlight advantages]** |

*Note: Price comparison alone is misleading. [Explain key differentiators that justify premium or highlight value gaps in cheaper alternatives.]*
```

## Payment Terms Section

Always include with any pricing presentation:

```markdown
### Payment Terms

- **Payment method**: [Invoice / credit card / ACH / wire transfer]
- **Net terms**: [Net 15 / Net 30] calendar days from invoice date
- **Late payment**: Interest accrues at [1.5]% per month on overdue balances
- **Service suspension**: [Provider reserves the right to suspend services for invoices overdue by more than 30 days]
- **Currency**: All amounts in [USD]
- **Taxes**: [Prices exclude applicable taxes / Prices include all taxes]
```

## Discount & Negotiation Levers

When a prospect pushes on price, these are structured concessions (always get something in return):

| We Concede | We Get In Return |
|-----------|-----------------|
| [X]% discount on project fee | Annual commitment on ongoing services (instead of monthly) |
| Payment terms extended (Net 30 instead of Net 15) | Full project scope maintained (no scope reduction) |
| Reduced pilot scope at lower price | Right to expand to full scope if pilot succeeds |
| Waive setup/onboarding fee | 12-month minimum commitment |
| First month free on ongoing services | Public case study / testimonial rights |
| Volume discount on usage tiers | Higher volume commitment |

**Hard floor**: Never go below $[minimum] for [full scope]. If price must drop further, reduce scope proportionally.

---

## Pricing Presentation Rules

1. **Value before price** — Always establish what the client gains before showing what they pay
2. **Anchor high** — Show the full value or build-vs-buy cost before showing your price
3. **Use "investment" not "cost"** — Language frames perception
4. **Break it down** — A $22,000 project feels smaller as "$8K setup + $5K customization + $6K AI + $3K support"
5. **Show the math** — ROI calculations make the price feel rational, not emotional
6. **Always have a fallback** — Prepare a reduced-scope option at a lower price before the meeting
7. **Never discount without getting something** — Every concession must be reciprocal
